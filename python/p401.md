## 1. Iterators, Generators, and Classic Coroutines

---

### 1.1. Iteration in Python

* Iteration: fundamental to data processing.
* Built-in support for the Iterator pattern.
* Collections are iterable in Python.

---

### 1.2. The `iter()` Built-in Function

* Automatically invoked by Python loops.
* Checks for `__iter__()` method, then falls back to `__getitem__()`.
* Usage with callable and sentinel values:

```python
iter(callable, sentinel)
```

* Example: Read file blocks until empty byte-string (`b''`).

---

### 1.3. Iterable vs. Iterator

* **Iterable:** Object returning an iterator (`__iter__`).
* **Iterator:** Object returning the next item (`__next__`).
* Iterators also implement `__iter__`, returning themselves.

Example:

```python
it = iter('ABC')
next(it)  # 'A'
```

---

### 1.4. Sentence #1: Sequence-based

* Implements sequence protocol (`__getitem__`, `__len__`).
* Uses `reprlib.repr` for concise representation.

```python
class Sentence:
    def __getitem__(self, index):
        return self.words[index]
```

---

### 1.5. Sentence #2: Classic Iterator Pattern

* Separates Iterable and Iterator:

```python
class SentenceIterator:
    def __next__(self):
        ...
```

* Creates new iterator each time `iter()` is called.

---

### 1.6. Generator Functions

* Pythonic approach using `yield`.
* Generator simplifies iterator implementation:

```python
def gen_words(text):
    for word in text.split():
        yield word
```

* No need for explicit iterator class.

---

### 1.7. Lazy Iteration

* `re.finditer` provides lazy evaluation:

```python
for match in re.finditer(r'\w+', text):
    yield match.group()
```

* Efficient memory usage.

---

### 1.8. Generator Expressions

* Concise alternative to generator functions:

```python
return (match.group() for match in re.finditer(r'\w+', text))
```

* Ideal for simple, inline generation.

---

### 1.9. Arithmetic Progression Generators

* Generate numeric series:

```python
def aritprog(begin, step, end=None):
    result = begin
    while end is None or result < end:
        yield result
        result += step
```

---

### 1.10. Standard Library Generators

* **Filtering**: `filter`, `dropwhile`, `takewhile`
* **Mapping**: `map`, `enumerate`, `accumulate`
* **Merging**: `chain`, `zip`, `product`
* **Expanding**: `combinations`, `permutations`
* **Rearranging**: `groupby`, `reversed`

---

### 1.11. Classic Coroutines

* Coroutines consume data, using `yield` as suspension point.
* Initiated explicitly (`next(gen)`):

```python
def coroutine():
    total = 0
    while True:
        num = yield
        total += num
```

---

### 1.12. Coroutine Delegation: `yield from`

* Delegates operations to sub-coroutine:

```python
yield from other_coroutine()
```

* Simplifies complex coroutine logic.

---

### 1.13. Coroutine Finalization

* Handle termination and cleanup:

```python
try:
    yield
finally:
    cleanup()
```

* Use `close()` method or context management.

---

### 1.14. Coroutines vs. Generators

* Generators produce data; Coroutines consume data.
* Clear semantic distinction:

| Generators     | Coroutines    |
| -------------- | ------------- |
| Produce output | Consume input |
| `next()`       | `send(value)` |

---

### 1.15. Chapter Summary

* Python provides powerful, built-in tools for iteration.
* Generators simplify complex iteration patterns.
* Coroutines enhance code clarity and manage stateful processes.
* Leverage standard library to avoid reinventing the wheel.

## 2. with, match, and else Blocks

---

### 2.1. Context Managers (`with`)

* Simplify resource management (`try/finally`)
* Ensure resources are reliably released (e.g., file closing)
* Common in Python's standard libraries (`sqlite3`, `threading`, `decimal`)

* **Protocol methods:**

* `__enter__()`: setup actions, returns managed resource
* `__exit__(exc_type, exc_value, traceback)`: cleanup actions, handles exceptions

---

### 2.2. Example Context Manager

```python
with open('file.txt') as f:
    data = f.read()

### 2. file automatically closed after block
```

* Simplifies repetitive cleanup code

---

### 2.3. Custom Context Manager

**LookingGlass Example**

* Temporarily reverses printed text

```python
class LookingGlass:
    def __enter__(self):
        self.original_write = sys.stdout.write
        sys.stdout.write = lambda text: self.original_write(text[::-1])
        return 'JABBERWOCKY'

    def __exit__(self, exc_type, exc_value, traceback):
        sys.stdout.write = self.original_write
```

---

### 2.4. Contextlib Module

* Built-in module to simplify context managers
* Useful functions:

  * `closing`: for objects with `.close()`
  * `suppress`: ignores specified exceptions
  * `nullcontext`: does nothing (conditional)
  * `@contextmanager`: simplifies manager creation
  * `ExitStack`: handles multiple context managers

---

### 2.5. Generator-based Context Managers

* Use `@contextmanager` to simplify class-based managers

```python
@contextmanager
def simple_context():
    print("Setup")
    yield
    print("Teardown")

with simple_context():
    print("Action")
```

---

### 2.6. Pattern Matching (`match/case`)

* Python 3.10 introduced `match/case`
* Enhances readability for complex control flows
* Ideal for handling structured data (like ASTs)

```python
match command:
    case "start":
        print("Starting...")
    case "stop":
        print("Stopping...")
    case _:
        print("Unknown command")
```

---

### 2.7. Scheme Interpreter Example

* Interpreter for Scheme expressions
* Matches patterns of parsed expressions clearly

```python
match exp:
    case int(x) | float(x):
        return x
    case Symbol(var):
        return env[var]
    case ['quote', x]:
        return x
```

* Great demonstration of interpreter patterns

---

### 2.8. Advanced Matching

* Or-patterns (`|` operator) allow multiple patterns:

```python
case 'lambda' | 'λ', [*parms], *body:
    return Procedure(parms, body, env)
```

* Ensures variables consistent across subpatterns

---

### 2.9. Closures (`Procedure` Class)

* Combines functions with their environment

```python
class Procedure:
    def __init__(self, parms, body, env):
        self.parms = parms
        self.body = body
        self.env = env

    def __call__(self, *args):
        local_env = dict(zip(self.parms, args))
        env = Environment(local_env, self.env)
        return evaluate(self.body[-1], env)
```

---

### 2.10. `else` in Loops

* `else` executes if loop finishes without `break`

```python
for item in items:
    if item == target:
        break
else:
    print("Target not found")
```

---

### 2.11. `else` in Exception Handling

* `else` executes if no exceptions occur

```python
try:
    risky_operation()
except Exception as e:
    handle_error(e)
else:
    proceed()
```

* Clear separation of error-prone and safe operations

---

### 2.12. EAFP vs LBYL

* **EAFP**: Easier to Ask Forgiveness than Permission

  * Uses `try` extensively
* **LBYL**: Look Before You Leap

  * Extensive condition checking with `if`
* Python encourages EAFP

---

### 2.13. Chapter Summary

* Context managers streamline setup and cleanup
* Pattern matching simplifies complex control flows
* `else` clauses enhance loop and exception clarity
* Python promotes readability and maintainability

## 3. Concurrency Models in Python

---

### 3.1. Introduction

* **Concurrency**: structure multiple tasks, possibly parallel.
* **Parallelism**: execute multiple tasks simultaneously.
* Python provides:

  * Threads
  * Processes
  * Coroutines (`asyncio`)
* Importance of external tools for scalability.

---

### 3.2. Key Concepts & Terms

* **Concurrency**: handle multiple pending tasks (multitasking).
* **Parallelism**: simultaneous execution (requires multiple cores).
* **Execution unit**: Process, Thread, Coroutine.
* **Queue**: Inter-task communication (FIFO).
* **Lock**: Synchronization primitive (mutex).
* **Contention**: Competition for resources.

---

### 3.3. Python and the GIL

* **Global Interpreter Lock (GIL)** limits concurrency in threads.
* Only one thread executes Python bytecode at a time.
* I/O-bound tasks are less affected.
* CPU-bound tasks suffer under GIL.
* Use `multiprocessing` to bypass GIL for CPU-intensive tasks.

---

### 3.4. Concurrent Hello World

* Demonstrates concurrency models using a spinner example:

* **Thread-based:**

```python
spinner = Thread(target=spin, args=('thinking!', done))
spinner.start()
```

* **Process-based:**

```python
spinner = Process(target=spin, args=('thinking!', done))
spinner.start()
```

* **Coroutine-based:**

```python
spinner = asyncio.create_task(spin('thinking!'))
await slow()
spinner.cancel()
```

---

### 3.5. Impact of the GIL

* Threads work fine for I/O-bound tasks.
* CPU-intensive tasks:

  * Threads limited by GIL.
  * Processes leverage multiple cores efficiently.
* Coroutine version must yield (`await asyncio.sleep(0)`) explicitly to stay responsive.

---

### 3.6. Homegrown Process Pool

* Example: Prime number checking using queues.
* Multiprocessing for CPU-intensive tasks.
* Poison-pill pattern for graceful shutdown:

```python
while n := jobs.get():
    results.put(check(n))
results.put(PrimeResult(0, False, 0.0))
```

* Performance significantly improved compared to threads.

---

### 3.7. Python in the Multicore World

* Historical reason for GIL: simplicity and performance.
* Today, overcome by external libraries and multiprocess designs.
* Python thrives despite concurrency limitations.

---

### 3.8. System Administration

* Python automates remote configurations.
* Tools:

  * Ansible
  * Salt
  * Fabric
* High performance via concurrency, not intensive CPU usage.

---

### 3.9. Data Science & Python

* Python widely adopted for data-intensive tasks.
* Libraries leveraging concurrency & parallelism:

  * NumPy, SciPy
  * TensorFlow, PyTorch
  * Dask (distributed computing)
* GPU and cluster utilization enhances parallel performance.

---

### 3.10. Server-side Web Development

* Architecture matters: Horizontal scalability.
* Common components:

  * Application cache: Redis, Memcached
  * Databases: PostgreSQL, MongoDB
  * Message queues: RabbitMQ, Redis

---

### 3.11. WSGI Application Servers

* Standard Python interface for HTTP servers.
* Common servers:

  * mod\_wsgi (Apache)
  * uWSGI
  * Gunicorn
* Handle requests, distribute load efficiently.

---

### 3.12. Distributed Task Queues

* Simplify task distribution.
* Examples:

  * Celery
  * Redis Queue (RQ)
  * Dramatiq
* Manage background jobs, leverage multiple cores or machines.

---

### 3.13. Lessons & Recommendations

* Threads:

  * Suitable for I/O-bound tasks.
  * Easy, but GIL is a limiting factor.

* Processes:

  * Best for CPU-bound tasks.
  * Manage complexity via queues and shared memory.

* Coroutines:

  * Ideal for high concurrency, non-blocking I/O.
  * Async code structure needs careful design.

---

### 3.14. Chapter Summary

* Python concurrency is powerful, despite inherent limitations.

* Choose the right tool/model:

  * Threads: Simplicity and I/O tasks.
  * Processes: CPU-intensive and multi-core leverage.
  * Coroutines: Async operations, high concurrency, efficiency.

* Embrace third-party libraries and patterns for scalable solutions.

## 4. Concurrent Executors in Python

---

### 4.1. Concurrent Web Downloads

* **Performance Comparison:**

* Sequential (`flags.py`): Slowest
* Threads (`flags_threadpool.py`): \~5 times faster
* Asyncio (`flags_asyncio.py`): Similar to threads

* **Code Basics:**

* URL-based downloads of country flag images
* Sequential vs concurrent execution
* Threaded execution leverages `ThreadPoolExecutor.map()` for simplicity

---

### 4.2. Sequential Script (`flags.py`)

* Basic downloading script, baseline for comparisons
* Functions:

  * `get_flag(url)`
  * `save_flag(image)`
  * `download_many(cc_list)`
* Downloads flags sequentially
* No concurrency, slow performance

---

### 4.3. Threaded Implementation

* `ThreadPoolExecutor.map()` simplifies threading
* Automatically manages thread pools and queueing tasks

```python
with ThreadPoolExecutor() as executor:
    results = executor.map(download_one, cc_list)
```

* Results gathered sequentially but executed concurrently

---

### 4.4. Futures Explained

* Represent asynchronous operations
* Created by the executor (`submit` method)
* Methods:

  * `.done()` → checks completion
  * `.result()` → retrieves result
  * `.add_done_callback()` → notifies on completion
* Futures managed internally, not directly by user

---

### 4.5. `as_completed` Method

* Allows iteration as tasks complete
* Useful for real-time progress tracking

```python
for future in as_completed(futures_list):
    result = future.result()
```

* Provides flexibility compared to `map`

---

### 4.6. Process-Based Concurrency

* `ProcessPoolExecutor` for CPU-bound tasks
* Bypasses Python's GIL (Global Interpreter Lock)
* Ideal for parallel computation

```python
with ProcessPoolExecutor() as executor:
    results = executor.map(check_prime, numbers)
```

* Results ordered by input, parallel execution

---

### 4.7. Multicore Prime Checker Example

* Prime checking rewritten for multi-processing
* Significant performance improvement
* Easy switch from threads to processes

```python
def check(n):
    return is_prime(n)
```

* Parallel execution simplified by executor

---

### 4.8. Executor.map Experiment

* Illustrates behavior clearly with sleep delays
* Three threads handling multiple tasks concurrently
* Tasks processed in batches, demonstrating worker availability

```python
executor = ThreadPoolExecutor(max_workers=3)
results = executor.map(loiter, range(5))
```

---

### 4.9. Advanced: Progress & Error Handling

* Enhanced scripts with:

  * Progress bar (`tqdm`)
  * Robust error handling
  * Verbose mode for detailed feedback

* Flags download with error simulation servers (LOCAL, REMOTE, DELAY, ERROR)

---

### 4.10. Error Handling Strategy

* HTTP status code handling (404 vs other errors)
* Exception propagation for critical errors
* Detailed counters for download status (`OK`, `NOT_FOUND`, `ERROR`)

```python
try:
    status = future.result()
except httpx.HTTPStatusError as exc:
    handle_error(exc)
```

---

### 4.11. Threadpool with `as_completed`

* Maps each future to metadata (country codes)
* Enables informative error messages
* Concurrent execution with detailed progress tracking

```python
to_do_map[future] = cc
for future in as_completed(to_do_map):
    cc = to_do_map[future]
```

---

### 4.12. Chapter Summary

* Concurrent tasks significantly speed up I/O-bound operations
* `concurrent.futures` abstracts complexities of threads and processes
* Futures central to managing asynchronous tasks
* `as_completed` offers dynamic task handling
* Executors simplify multicore CPU tasks effectively

## 5. Asynchronous Programming

---

### 5.1. Coroutine Types

* **Native coroutine**: Defined with `async def`.
* **Classic coroutine**: Uses generator (`yield`), deprecated.
* **Generator-based coroutine**: Decorated with `@types.coroutine`.
* **Async generator**: Uses `async def` and `yield`.

```python
async def native_coro():
    await some_async_op()
```

---

### 5.2. asyncio and Domain Probing

* DNS probing script (`blogdom.py`):
* `asyncio.as_completed()` handles coroutines concurrently.

```python
async def probe(domain):
    loop = asyncio.get_running_loop()
    try:
        await loop.getaddrinfo(domain, None)
    except:
        return False
    return True
```

---

### 5.3. Async HTTP Clients with HTTPX

* **Simple Flag Downloader:**

  * Uses `asyncio.gather` for concurrent HTTP requests.

* **Enhanced Downloader:**

  * Progress bar with `tqdm`.
  * Error handling (HTTP, Request errors).
  * Avoid blocking: `await asyncio.to_thread()` for file I/O.

---

### 5.4. Async HTTP Clients (cont.)

* **Multiple Requests per Task:**

  * Sequential async requests with clear, linear code.

  ```python
  async def download_one(client, cc):
      flag = await get_flag(client, cc)
      country = await get_country(client, cc)
      save_flag(flag, f"{country}.gif")
  ```

---

### 5.5. Request Throttling with Semaphores

* Control concurrent operations.

```python
semaphore = asyncio.Semaphore(10)

async with semaphore:
    await get_flag(client, cc)
```

---

### 5.6. Executors: Threads and Processes

* Use `asyncio.to_thread()` (Python 3.9+)
* Older Python versions use `run_in_executor()`.
* Great for blocking tasks (e.g., disk I/O).

```python
await asyncio.to_thread(save_file, data, path)
```

---

### 5.7. Writing Async Servers

* **FastAPI Web Service:**

  * FastAPI simplifies building async web services.
  * Type hints and decorators reduce boilerplate.

  ```python
  @app.get('/search')
  async def search(q: str):
      results = index.search(q)
      return [{'char': c, 'name': name(c)} for c in results]
  ```

---

### 5.8. Async TCP Server

* Use `asyncio.start_server`.
* Handle clients with `StreamReader` and `StreamWriter`.

```python
async def handle_client(reader, writer):
    data = await reader.readline()
    writer.write(process(data))
    await writer.drain()
```

---

### 5.9. Asynchronous Iteration

* Async iteration with `async for`.
* Objects implement `__aiter__()` and `__anext__()`.

```python
async for row in cursor:
    process(row)
```

---

### 5.10. Async Generators

* Use `async def` with `yield`.

```python
async def async_gen():
    for item in data:
        await asyncio.sleep(1)
        yield item
```

---

### 5.11. Python Async Console

* Start with `python -m asyncio`.
* Allows `await` directly at REPL.

```shell
>>> await asyncio.sleep(1, 'Done')
'Done'
```

---

### 5.12. Best Practices

* Async programming can improve performance significantly.
* Not suitable for CPU-bound tasks (use process executors).
* All-or-nothing approach for best results (avoid blocking calls).
* Utilize existing async libraries like FastAPI, HTTPX, aiopg, asyncpg.

---

### 5.13. Chapter Summary

* asyncio enables high-performance concurrent applications.
* Async code can be as readable as synchronous code.
* Important to understand async constructs and their correct usage.
